Floppy Disk Shooting Game
Siv3D風Renderer統合 実装仕様書

対象実装者: Luna
作成日: 2026-08-22

======================================================================
1. 目的
======================================================================

現在追加されているSiv3D風Renderer APIを、記録だけの仮実装から実際に画面へ描画できる
完成した経路へ発展させる。

本仕様の最終状態:

- Renderer::Draw()で登録した描画コマンドがGPUへ送信される
- Circle、Rect、Textが同じ遅延描画方式で処理される
- ISceneとSceneManagerがD3D12RenderingServiceではなくRendererを受け取る
- ゲームコードからDirectX 12バックエンドへの依存を段階的に除去できる
- テストプロジェクトがビルド・リンク・実行できる
- 既存ゲームの見た目と動作を壊さない

この作業はRenderer経路の完成を目的とする。Camera、ResourceManager、すべての3D描画の
全面移行は本仕様の対象外とする。

5. 目標フレーム処理
======================================================================

最終的なmain.cppの描画部分は概ね以下とする。

renderer.BeginFrame();
app.Render(renderer);
renderer.EndFrame();

処理順:

1. Renderer::BeginFrame
2. バックエンドのBeginFrame
3. コマンド領域をリセット
4. SceneがRenderer::Draw／DrawText／SetPipelineを呼ぶ
5. Renderer::EndFrame
6. Renderer::Flush
7. 記録順にコマンドをバックエンドへ実行
8. バックエンドのEndFrame

EndFrame内でFlushする。
必要ならFlushをpublicにしてもよいが、通常利用ではEndFrameだけで完結させる。


======================================================================
6. Renderer公開API
======================================================================

最低限、以下を提供する。

class Renderer {
public:
    static constexpr std::size_t MaxCommands = 4096;

    void BeginFrame();
    void Draw(const Circle& circle, const ColorF& color);
    void Draw(const Rect& rect, const ColorF& color);
    void DrawText(std::string_view text,
                  const Vector2& position,
                  float size,
                  const ColorF& color);
    void SetPipeline(PipelineId pipeline);
    void Flush();
    void EndFrame();

    std::size_t CommandCount() const;
    std::size_t DroppedCommandCount() const;
    bool HasOverflowed() const;
};

規則:

- Draw系はバックエンドを即時操作しない
- SetPipelineもバックエンドを即時操作しない
- Flushだけが記録済みコマンドを実行する
- Flush後に同じコマンドを再実行しない
- EndFrameは未FlushならFlushしてからPresent相当を行う
- バックエンドなしのRendererでもコマンド記録テストができる
- MaxCommands超過時はクラッシュせず、超過数を記録する
- デバッグビルドではフレームごとに一度だけ警告してよい


======================================================================
7. RenderCommand
======================================================================

現在の固定容量設計を維持してよい。

必須Type:

- Circle
- Rect
- Text
- Pipeline

保持情報:

- Type
- 図形データ
- ColorF
- Textの位置、サイズ、文字列
- PipelineId

規則:

- Command生成時は以前のデータを残さない
- Textは終端NULLを保証する
- 長すぎるTextは固定容量へ安全に切り詰める
- 切り詰めたことをテスト可能にする
- RenderCommandからD3D12型を参照しない

std::variantは使用してもよいが、バイナリサイズとコンパイルコストを考慮し、現在の単純な
固定構造を維持してもよい。


======================================================================
8. バックエンド境界
======================================================================

推奨案:

Engine/Graphics/IRenderBackend.hを追加する。

class IRenderBackend {
public:
    virtual ~IRenderBackend() = default;
    virtual void BeginFrame() = 0;
    virtual void DrawCircle(const Circle&, const ColorF&) = 0;
    virtual void DrawRect(const Rect&, const ColorF&) = 0;
    virtual void DrawText(std::string_view,
                          const Vector2&,
                          float,
                          const ColorF&) = 0;
    virtual void SetPipeline(PipelineId) = 0;
    virtual void EndFrame() = 0;
};

D3D12RenderBackendまたはD3D12RenderingService Adapterがこれを実装する。

ただし、既存コードへの変更量が大きすぎる場合は、第一段階ではRenderer.cpp内部に
D3D12RenderingServiceへの変換処理を置いてよい。その場合でもRenderer.hと
RenderCommandへDirectX 12型を露出させないこと。

テスト容易性を優先し、可能ならFakeRenderBackendを作ること。

FakeRenderBackendで検証するもの:

- BeginFrameが最初に呼ばれる
- コマンドが登録順に実行される
- TextがFlush前に実行されない
- PipelineがFlush前に変更されない
- EndFrameが最後に呼ばれる
- Flushを二回呼んでも二重実行されない


======================================================================
9. CircleとRectの実描画
======================================================================

CircleとRectは最終的に画面へ描画されなければならない。

第一版では既存のプロシージャル形状シェーダーを利用してよい。

Circle:

- centerを2D位置として扱う
- radiusから幅と高さを生成する
- ColorFを定数バッファへ転送する
- 円形用shapeTypeまたは専用Pipelineを使用する

Rect:

- positionの意味を既存Geometry定義と一致させる
- sizeから幅と高さを生成する
- ColorFを定数バッファへ転送する

座標系:

- 第一版は既存の描画座標系へ合わせてよい
- ピクセル座標かNDCかをRenderer.hのDoxygenへ明記する
- CircleとRectで異なる座標系を使わない
- 将来の仮想画面対応を妨げない変換関数へ集約する

重要:

単体テストが通るだけでなく、実行時にCircleとRectが見えることを確認する。

10. Scene API移行
======================================================================

Application/Interfaces/IScene.h:

変更前:

virtual void Render(D3D12RenderingService& renderer) = 0;

変更後:

virtual void Render(Renderer& renderer) = 0;

Application/UseCases/SceneManager.h:

void Render(Renderer& renderer);

Presentation/Scenes/TitleScene:

- Render(Renderer&)へ変更
- タイトル文字はRenderer::DrawTextを使用する
- 動作確認用にCircleまたはRectを一つ描画してもよい
- 確認用図形を残す場合はタイトル画面の正式な装飾として意味を持たせる

Presentation/Scenes/TestStage:

- Render(Renderer&)へ変更
- ShootingGameの移行が完了していない間だけ、Rendererから互換バックエンドを得る
  逃げ道を作らず、明示的なLegacyRenderContextを渡す方式を検討する
- 公開APIにD3D12RenderingService&を戻さない

推奨移行方法:

Rendererへ一時的なLegacyDrawコールバックまたは限定された3D描画APIを追加し、
ShootingGameが必要な描画命令をRendererへ依頼する。

禁止:

- Renderer::GetD3D12Backend()
- Renderer::GetCommandList()
- Renderer::GetConstantBufferData()

これらを追加すると抽象化が無意味になるため禁止する。

11. 既存3D描画の段階移行
======================================================================

本仕様ではShootingGame.h全体を一度に移行しない。

最低限の移行対象:

1. 背景またはUI矩形のどちらか一種類
2. TitleSceneのText
3. 動作確認用CircleまたはRect

追加してよい最小3D API:

struct Primitive3D {
    PrimitiveShape shape;
    Transform transform;
    ColorF color;
};

void Renderer::Draw(const Primitive3D& primitive);

または:

- DrawBox
- DrawSphere
- DrawCylinder
- DrawCone
- DrawPlate

ただし、ゲーム側へshapeType整数、vertexCount、定数バッファindexを渡してはいけない。

Renderer内部で以下を決める。

- Pipeline
- shapeType
- vertexCount
- 定数バッファ割り当て

既存ShootingGameの描画を移行する際は、一種類ずつ置き換えて見た目を比較する。

12. 画面サイズとアスペクト比
======================================================================

本仕様ではCameraの完成までは要求しないが、800.0f / 600.0fの固定値は解消する。

D3D12RenderingServiceまたはRendererから以下を取得可能にする。

- Width()
- Height()
- AspectRatio()

規則:

- Heightが0の場合の除算を防ぐ
- 初期化時の1920×1080を正しく返す
- 将来のWM_SIZE対応時に更新可能な設計にする
- ShootingGameのProjection行列はAspectRatio()を使用する

14. RendererTestsの必須ケース
======================================================================

既存Tests/RendererTests.cppを拡張する。

必須:

1. BeginFrameで前フレームのコマンドが消える
2. Circleが正しい値で記録される
3. Rectが正しい値で記録される
4. Textが正しく終端される
5. 長いTextがバッファを越えない
6. Pipelineが正しく記録される
7. Flushで登録順に実行される
8. Flush前にはバックエンドが呼ばれない
9. Flush二回で二重実行されない
10. EndFrameが未実行コマンドをFlushする
11. MaxCommandsを越えてもクラッシュしない
12. DroppedCommandCountが正しい
13. BeginFrameでoverflow状態がリセットされる
14. バックエンドなしでも記録操作が安全である

FakeRenderBackendを使う場合、実行されたイベントをvectorへ記録して順序を検証する。
